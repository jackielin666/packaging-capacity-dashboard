# 每月自動備份到 Google Drive —— 安裝步驟

## 為什麼要做

Supabase 免費方案**沒有自動備份**。資料只存在一個地方，帳號出事就全沒了。
這支程式跑在 Google 自己的機器上，每月 1 號凌晨自動把整個資料庫匯出成 CSV，
存進你的 Drive 資料夾。不用開電腦、不用伺服器、不用付錢。

備份位置：[包裝產能資料庫備份](https://drive.google.com/drive/folders/1FXHhPneNgMc4H11ZzrFbnhF1h-B-v9vq)

---

## 前置條件

Supabase 後台要先開放 `packing` schema，這支程式才讀得到資料：

> Project Settings → API → **Exposed schemas** → 加入 `packing` → Save

沒做這步，執行時會出現 `406` 或 `The schema must be one of the following` 錯誤。

---

## 安裝（約 5 分鐘，只需做一次）

### 第 1 步　建立指令碼專案

1. 開 <https://script.google.com>
2. 左上角 **新增專案**
3. 專案名稱改成「包裝產能資料庫備份」

### 第 2 步　貼上程式

1. 把左邊預設的 `Code.gs` 內容**全部刪掉**
2. 貼上備份程式，**全部複製**，貼進去。程式碼有三個地方可以拿，挑順手的：
   - Drive 備份資料夾裡的 **`安裝用_備份程式_Code.gs.txt`**（點開就能全選複製，最方便）
   - 本資料夾的 `Code.gs`
   - 和 Jackie 哥對話中直接貼的那段
3. 按 💾 儲存

### 第 3 步　設定密碼

密碼不寫在程式裡，寫在另一個地方，這樣程式就算被別人看到也沒關係。

1. 左邊齒輪圖示 **專案設定**
2. 捲到最下面 → **指令碼屬性** → **新增指令碼屬性**
3. 填入：

   | 欄位 | 內容 |
   |---|---|
   | 屬性 | `BACKUP_PASSWORD` |
   | 值 | （Jackie 哥另外收到的那組密碼） |

4. **儲存指令碼屬性**

### 第 4 步　手動跑一次，確認會動

1. 回到 **編輯器**
2. 上方函式下拉選單選 **`runBackup`** → 按 **執行**
3. 第一次會跳出授權視窗：
   - 「Google 尚未驗證這個應用程式」→ 點 **進階** → **前往「包裝產能資料庫備份」（不安全）**
   - 這是你自己寫的程式，不是別人的，所以安全
   - 按 **允許**
4. 下方「執行記錄」出現 `備份完成` 就成功了
5. 去 Drive 資料夾看，應該多出三個檔案：

   ```
   packing_skus_20260914.csv          品項主檔
   packing_batches_20260914.csv       批次記錄（主資料）
   packing_daily_status_20260914.csv  無作業日標記
   ```

### 第 5 步　排定每月自動執行

1. 函式下拉選單選 **`installMonthlyTrigger`** → 按 **執行**
2. 執行記錄出現「已排定：每月 1 號凌晨 3 點自動備份」即完成

之後就不用管了。

## 平常怎麼確認備份是好的

備份最危險的情況不是「沒跑」，是**「有跑，但檔案是空的」** —— 看起來一切正常，
真的要用的時候才發現沒東西。所以多寫了一個檢查函式。

選 **`verifyLatestBackup`** → **執行**，執行記錄會長這樣：

```
✔ skus：資料庫 110 筆、備份 110 筆（packing_skus_20260914.csv）
✔ batches：資料庫 1593 筆、備份 1593 筆（packing_batches_20260914.csv）
✔ daily_status：資料庫 0 筆、備份 0 筆（packing_daily_status_20260914.csv）
```

**全部是 ✔ 就沒問題。出現 ⚠ 代表備份跟資料庫對不起來，要查。**
建議每季跑一次，30 秒的事。

## 設計上的幾個決定

| 決定 | 原因 |
|---|---|
| 用**唯讀帳號**（`backup@packing.local`，角色 `viewer`） | 備份只需要讀。密碼萬一外流，對方也改不了、刪不掉任何資料 |
| 密碼放**指令碼屬性**，不放程式裡 | 程式碼會進 GitHub，密碼不會 |
| **不匯出工時欄位** | 工時是資料庫從起訖時間算出來的。存進 CSV 只會製造第二份真相，日後對不上時不知道該信誰 |
| 保留最近 **24 份**，更舊的自動丟垃圾桶 | 兩年份足夠回溯，又不會把 Drive 塞爆 |
| 一張表一個檔，不合併 | 還原時可以只還原壞掉的那張表 |

---

## 還原方式

CSV 可以直接用 Excel 或 Google 試算表打開檢查。
真的要整份還原時，執行 `system/supabase/migrations/` 裡的三個 SQL 重建結構，
再把 CSV 匯入對應資料表即可 —— `batches` 的工時欄位會自動重算，不用也不能匯入。
