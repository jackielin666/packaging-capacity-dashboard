# 包裝產能系統（開發中）

目標形態：專人每天／每週在網頁介面 key in 每批包裝資料 → 永久存進資料庫 →
月初自動檢核完整性 → 一鍵產生儀表板 → 一鍵下載當月 PDF 簡報。

目前的 `../index.html`（上傳 xlsx 即出結果）維持不動，兩者並行；
系統上線後，儀表板改為直接讀資料庫，xlsx 版本仍可作為離線備援。

## 階段 0 成果

**Supabase 專案**：`smart-equipment-patrol`（`vnncuksjvdsxwveomoww`，ap-northeast-1）
使用獨立的 `packing` schema，與既有巡檢系統的 `public` schema 完全隔離。

### 資料表

| 資料表 | 用途 | 筆數 |
|---|---|---|
| `packing.skus` | 品項主檔（品名、單件重量、容器型式） | 110 |
| `packing.batches` | 批次記錄（主表） | 1,593 |
| `packing.daily_status` | 標記「當日確實無包裝作業」 | 0 |
| `packing.members` | 使用者角色 | 1 |
| `packing.audit_log` | 稽核記錄（任何異動自動留痕，不可竄改） | — |

### 兩個關鍵設計

**1. 工時是「算出來的」，不是「填進去的」**

`batches.hours` 是 generated column，永遠等於 `(結束 − 起始)`，跨午夜自動加 24 小時。
原始 Excel 裡有 3 筆人工填的工時與起訖時間對不上；改成資料庫自動推算後，
這類錯誤在結構上就不可能再發生。

**2. 「沒生產」與「忘了登記」要分得開**

`daily_status` 讓輸入專員按一個「本日無包裝作業」按鈕。
沒有批次記錄、又沒有這個標記的日期，才算漏登 —— 這是階段 2 月度檢核的判定基礎。

### 權限（RLS）

| 角色 | 讀 | 寫 |
|---|---|---|
| `operator` 輸入專員 | 全部 | 只能新增，且**只能修改當月**資料 |
| `manager` 主管 | 全部（含稽核記錄） | 不限月份 |
| `viewer` 檢視者 | 全部 | 不可寫 |

月份限制用台灣時區判定（`packing.today_tw()`），避免 UTC 造成月初月底誤判。
稽核記錄已 `revoke` 掉所有寫入權限，只有觸發器能寫。

## 登入方式

使用者只輸入**帳號**，不輸入信箱：

```
帳號：admin000
密碼：（自行設定）
```

Supabase Auth 底層一定要用信箱格式，所以前端會自動把 `admin000` 補成
`admin000@packing.local` 再送出。**使用者從頭到尾看不到信箱**，也不用記。
日後新增輸入專員時同理：帳號 `packer01`，後面自動補 `@packing.local`。

| 帳號 | 角色 | 用途 |
|---|---|---|
| `admin000` | manager 主管 | Jackie 哥，不限月份可改 |
| `pack01` | operator 輸入專員 | 廠務助理，新增不限日期、修改只限當月 |
| `backup` | viewer 唯讀 | 每月備份程式專用，只能讀 |

新增帳號用 `packing.create_login('帳號', '密碼', '顯示名稱', '角色')`，
不要再手寫 insert —— 漏掉 auth.users 的那八個欄位會讓登入回 500。

## 階段 1 成果：輸入介面 `entry.html`

網址（合併到 main 後）：
`https://jackielin666.github.io/packaging-capacity-dashboard/entry.html`

和儀表板一樣是單一 HTML 檔，沒有打包工具、沒有框架、不依賴外部套件網站
—— 工廠內網擋掉 CDN 也照樣能開。

### 現場怎麼用

| 動作 | 做法 |
|---|---|
| 打時間 | 直接打 `0800`，離開欄位自動變 `08:00`。也接受 `800`、`8`、`8:00` |
| 選品項 | 打品號前兩碼即出現候選，常做的排在前面 |
| 換欄位 | Enter 往下一格；打到最後一格自動開新的一列，手不用離開鍵盤 |
| 從 Excel 搬 | 整塊複製貼上（品項／起始／結束／瓶數／人數），一次填好多列 |
| 當天沒做 | 按「標記本日無包裝作業」 |
| 找漏登的日子 | 按「跳到待補的日期」，自動找回最早一個沒處理的工作日 |

工時和產能是邊打邊算的，不用填也填不了。

### 系統檢查清單

表格底下有一塊即時更新的清單，分三種：

| 類型 | 會不會擋儲存 | 內容 |
|---|---|---|
| **待處理** | ✅ 擋 | 欄位沒填完、品號不在主檔、結束時間等於起始 |
| **待確認** | ❌ 不擋 | 產能偏離平常水準、同品項時間重疊、沒填人數 |
| **通過** | — | 已經檢查過沒問題的項目 |

表格本身只顯示數字加一個小圓點，**原因寫在清單裡**。這樣表格不會被說明文字
撐開，也不會每一列都在喊。每一項都有「前往修正」或「查看該列」可以直接跳過去。

### 四個刻意的設計

**1. 異常當場抓，不等月底**

每打完一批就比對該品項的歷史水準，低於平均 ×0.7 或高於 ×2.5 就列進待確認。
這種數字九成是瓶數或時間打錯 —— 當下抓到，比月底對帳再回頭查省事得多。
批次數不足 10 批的品項不示警，樣本太少沒有判斷力。

**「確認無誤」會存進資料庫。** 專員確認「這批真的就是慢」本身就是資訊，
儀表板日後可以把離群批次分成「已由現場確認」與「尚未說明」兩類。
一旦瓶數或時間被改過，確認會自動失效 —— 確認的是那組數字，不是那一列。

**1-2. 時間重疊只檢查同一支品項**

跨品項的時間重疊**不檢查**。11 個月的真實資料裡，243 個工作日中有 **149 天**
出現跨品項重疊（61%），因為多條線並行本來就是常態。把它當異常會天天誤報，
兩週後整塊清單就會被當成雜訊忽略 —— 連真正的錯誤也一起。

同品項重疊在同一段期間只有 **2 筆**，而且兩筆看起來都是打錯：

| 日期 | 品項 | 兩批時間 |
|---|---|---|
| 2026-02-11 | B2011 | 16:00–**19:50** ／ **19:00**–20:30 |
| 2026-07-09 | D0991 | 08:30–**12:00** ／ **11:30**–16:00 |

0.13% 的誤報率才有資格當檢查規則。

**3. 新增和修改的權限分三層**

| 動作 | 輸入專員 | 主管 |
|---|---|---|
| 新增批次 | ✅ 任何日期 | ✅ |
| 修改整筆（品項／時間／瓶數） | 上個月 1 號之後 | ✅ 不限 |
| **補人數、備註、確認異常** | ✅ **任何日期** | ✅ |
| 刪除 | 上個月 1 號之後 | ✅ 不限 |

**人數為什麼要開放到任何日期**：它是階段 4 人均效率分析唯一的依據，
補登會拖很長，不可能都落在當月。**量測值為什麼要保護**：品項、時間、
瓶數改掉就沒有第二份可以對照了。

「上個月 1 號」這條線是給實務用的 —— 月初才收到上個月月底的資料，
登記完發現打錯還來得及自己改，不用每次都找主管。

資料庫端用 RLS 管「哪幾列」、觸發器管「哪幾欄」（RLS 沒有欄位層級），
前端的判斷與資料庫是同一套定義，兩邊都擋。

**3-2. 系統上線前的空白日不算漏登**

2026-09 之前的資料整批從 Excel 匯入，而 **Excel 裡沒有「那天沒生產」這種紀錄**。
Jackie 哥確認：那段期間看到的空白日就是當天沒生產。

所以月曆上那些日子顯示為淺灰（歷史空白），不標紅、不列入待補、
「跳到待補的日期」也會跳過。分界點由資料自己決定 ——
查 `source = 'import'` 的最後一個生產日期（目前是 2026-08-31），不寫死。

**4. 今天不算漏登**

當天還沒過完就標紅字，每天早上打開都在示警，久了會被當成雜訊直接忽略。
只有「今天以前」的工作日才會被算成待補。

### 匯出

月曆下方可以把紀錄下載成 CSV，範圍選本月／近三個月／全部。
檔案開頭加了 BOM，**Excel 直接打開不會變亂碼** —— 這是現場最常回報的問題。
欄位含算好的產能，以及「已確認異常」，開起來就能用。

### 品項歷史

品號旁邊有「歷史」，點開看得到這支產品平常做多快：平均、中位數、偏低門檻、
最近 60 批的明細，以及一條分布帶 —— **每一點是一批，正在輸入的這批用綠色大點
標出來**，一眼就知道它落在哪裡。

這是為了讓「確認無誤」有依據。畫面提醒「這批偏低」時，現場需要證據才能判斷
要不要按下去，而不是憑印象。

## 階段 2 成果：補登與檢核

輸入頁最下方多一個面板，回答兩個問題：

| 問題 | 呈現 |
|---|---|
| 哪些工作日該登記卻沒登記 | 每月一列，待補天數標紅，點月份跳過去 |
| 人數補登到哪了 | 每月一條進度條，下方顯示合計 |

上方有一行狀態：有漏登就是橘色警示加「前往最早的一天」，全部處理完就變綠色。
**登記完數字會自己減少**，不需要另外回報。

### 一個刻意不做的判斷

匯入的歷史月份（2025-10 ～ 2026-08）**不列入待補**，即使那些月份有 23 個
工作日沒有任何批次。

原因：那些資料來自 Excel，而 Excel 裡沒有「那天沒生產」這種紀錄 —— 空白的
日子無從判斷究竟是沒做還是漏記。把它們當成待辦丟出去，就是 23 件查不出答案
的假工作。**清單一旦混進查不到答案的項目，整份清單就會被放棄**，連真正的
漏登也一起被忽略。

所以檢核只對系統上線後的月份負責，歷史月份標示為「匯入」。
待補天數因此從 34 降到 11（全部集中在 2026-09）。

### 為什麼先不接 Email 或 LINE

主動通知要有人看、看了要有反應，否則只是多一個被靜音的來源。
**先讓提醒待在每天都會打開的那個畫面上**，跑一兩個月，看實際會不會漏，
再決定要不要加。

## 階段 3 成果：儀表板讀資料庫 + 月報

### 儀表板的三種資料來源

| 來源 | 誰會用到 | 需要登入 |
|---|---|---|
| **內建快照** | 任何人打開連結（業務、生管、主管） | ❌ |
| **資料庫最新資料** | 登入後自動切換 | ✅ |
| 自己上傳的 Excel | 離線或比對用 | ❌ |

輸入頁與儀表板在同一個網域，**登入狀態是共用的** —— 廠助或主管在輸入頁登入過，
打開儀表板就直接是最新的，不用再按任何按鈕。

沒登入的人看到內建快照，來源列會標明 **「內建快照（到 YYYY-MM-DD）」**，
不會讓人誤以為那是最新數字。**這個頁面維持公開，不強迫登入**（Jackie 哥決定）。

### 月報（第 06 節）

選月份 → 產生 → 用瀏覽器的「列印 → 另存為 PDF」。**不引用任何外部套件**，
工廠內網擋 CDN 也印得出來。約 2 頁 A4，內容：

| 段落 | 內容 |
|---|---|
| 01 當月概況 | 包裝量／工時／整體產能／批次／作業日，各附與上月的比較 |
| 02 當月產出品項 | 前 12 名，含「當月產能 vs 該品項平常水準」 |
| 03 需要說明的批次 | 該月離群批次，最多 25 筆 |
| 04 吃工時但產量不高 | **收件者是業務與生管**，措辭明講不是包裝的問題 |
| 05 資料完整性 | 該月登記幾天、待補幾天、人數覆蓋率 |

**月份範圍的數字只算該月，但「算不算離群」的門檻沿用該品項的全期平均** ——
一個月的樣本不足以定義什麼叫正常，而且門檻要跟畫面上看到的一致。

第 05 段需要登入才讀得到；沒登入時直接寫「未登入，無法檢核」，
不會假裝知道。**一份沒說清楚涵蓋範圍的報表，比沒有報表更容易誤導。**

## 交給設計時怎麼做

直接把 `entry.html` 交出去只會看到登入畫面 —— 主畫面要連上資料庫才出得來。
所以用 `system/make_mockup.py` 產生一份靜態稿：

```
python3 system/make_mockup.py
```

它會用攔截網路請求的方式跑一次真實頁面、填入示範資料、把輸入值寫成 HTML 屬性、
移除所有程式碼，輸出 `design/entry-mockup.html`。**這份檔案單獨打開就能看到完整畫面。**

改樣式時有四樣東西不能動，檔案開頭的註解也寫了：

| 不能改 | 原因 |
|---|---|
| `id="..."` | 程式靠這些找元素 |
| `data-f="..."` | 輸入欄位對應到哪個資料欄位 |
| 表格列的 8 格結構（第 6 格工時、第 7 格產能） | 這兩格由程式即時算出來填入 |
| `bad`／`low`／`high`／`has`／`none`／`miss`／`today`／`locked` | 狀態樣式，程式會動態加減 |

顏色、字體、間距、圓角、陰影、排版順序都可以隨意改。
設計定案後把新樣式套回 `entry.html`，再跑一次 `system/test_entry.py` 確認沒改壞。
