# 包裝產能系統（開發中）

目標形態：專人每天／每週在網頁介面 key in 每批包裝資料 → 永久存進資料庫 →
月初自動檢核完整性 → 一鍵產生儀表板 → 一鍵下載當月 PDF 簡報。

目前的 `../index.html`（上傳 xlsx 即出結果）維持不動，兩者並行；
系統上線後，儀表板改為直接讀資料庫，xlsx 版本仍可作為離線備援。

## 階段 0 成果

**Supabase 專案**：`smart-equipment-patrol`（`vnncuksjvdsxwveomoww`，ap-northeast-1）
使用獨立的 `packing` schema，與既有巡檢系統的 `public` schema 完全隔離。

### 資料表

| 資料表 | 用途 | 筆數 |
|---|---|---|
| `packing.skus` | 品項主檔（品名、單件重量、容器型式） | 110 |
| `packing.batches` | 批次記錄（主表） | 1,593 |
| `packing.daily_status` | 標記「當日確實無包裝作業」 | 0 |
| `packing.members` | 使用者角色 | 1 |
| `packing.audit_log` | 稽核記錄（任何異動自動留痕，不可竄改） | — |

### 兩個關鍵設計

**1. 工時是「算出來的」，不是「填進去的」**

`batches.hours` 是 generated column，永遠等於 `(結束 − 起始)`，跨午夜自動加 24 小時。
原始 Excel 裡有 3 筆人工填的工時與起訖時間對不上；改成資料庫自動推算後，
這類錯誤在結構上就不可能再發生。

**2. 「沒生產」與「忘了登記」要分得開**

`daily_status` 讓輸入專員按一個「本日無包裝作業」按鈕。
沒有批次記錄、又沒有這個標記的日期，才算漏登 —— 這是階段 2 月度檢核的判定基礎。

### 權限（RLS）

| 角色 | 讀 | 寫 |
|---|---|---|
| `operator` 輸入專員 | 全部 | 只能新增，且**只能修改當月**資料 |
| `manager` 主管 | 全部（含稽核記錄） | 不限月份 |
| `viewer` 檢視者 | 全部 | 不可寫 |

月份限制用台灣時區判定（`packing.today_tw()`），避免 UTC 造成月初月底誤判。
稽核記錄已 `revoke` 掉所有寫入權限，只有觸發器能寫。

### 與現行儀表板數字的差異（已查明，非匯入錯誤）

儀表板內建的是舊檔（到 8/26），資料庫用的是最新檔（到 8/31）：

| 差異 | 筆數 | 說明 |
|---|---|---|
| 8/27～8/31 新增批次 | 22 | 舊檔尚未涵蓋的月底五天，含新品項 `Z2001` |
| `D0310` 5/16 兩筆補上瓶數 | 2 | 舊檔該欄空白故未納入，新檔已補 409 / 508 |
| `D0530` 8/6 瓶數更正 | 1 | 319 → 1,500 |

合計 +22 批、+45,554 瓶、+56.9 工時；整體產能兩者同為 **777**。
