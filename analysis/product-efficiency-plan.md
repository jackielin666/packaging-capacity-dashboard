# 品項全流程效率系統（product-efficiency）—— 執行計畫

> 每一步完成後停下來，由 Jackie 哥驗收，確認後才進行下一步。

## 目的

把「產品工時及製成率統計」（製造、充填）與「包裝產能」（成品包裝）兩個系統的資料
接在一起，讓每個品項從製造到包裝都有人時數據。資料逐月累積後用來：

1. 算出各品項的**標準工時**（人時/千瓶），用於估算人力成本
2. 每月 Review，找出**效率異常**的品項
3. 看出人力瓶頸落在**哪一段**（製造／充填／包裝）

## 三、系統架構

```
[生管] 製成率 Excel ──每月初上傳──▶ product-efficiency／匯入頁 ──┐
                                                               ▼
                                      Supabase（smart-equipment-patrol）
                                      ├─ packing     包裝（既有，不動）
                                      ├─ production  製造／充填／製成率（新增）
                                      └─ 整合 view    品項 × 月份 全流程人時
                                                               ▲          │
[廠務助理] 包裝輸入頁（照常）───────────────────────────────────┘          ▼
                                      product-efficiency／儀表板（入口網站第 3 張卡）
```

| 帳號 | 角色 | 在新系統能做什麼 |
|---|---|---|
| `admin000` | manager | 看儀表板、**上傳製成率 Excel** |
| `pack01` | operator | 看儀表板（不能匯入） |
| `backup` | viewer | 每月備份程式讀取 |

### 新增的資料表（`production` schema）

| 資料表 | 內容 | 對應 Excel |
|---|---|---|
| `production.runs` | 每日每品項：鍋數、半成品數(預估/實際)、成品數(實際)、不良品數 | 資料總表 |
| `production.labour` | 每日每品項：製造段、充填段的人數、前置、起訖時間，以及 O 欄表列人時 | 工時 |
| `production.imports` | 匯入記錄：誰、何時、哪個檔案、每月筆數 | —（資料齊全度檢核用） |
| `production.settings` | 工時費率、異常門檻等參數 | — |

**設計原則**（與包裝系統相同）：

- **人時用算的，不用填的**：資料庫只存起訖時間與人數，人時由資料庫依照製成率系統的規則推算（扣 12:00–13:00 午休、加前置時間）。
- **匯入以「月」為單位整月覆蓋**：同一個檔案匯入兩次，結果不變。Excel 是唯一來源，資料庫永遠與最新一版 Excel 一致。
- **匯入前先預覽差異**：列出每個月「原本幾筆 → 匯入後幾筆」。若某個月筆數減少超過 10%，要再確認一次才能寫入，避免上傳錯檔把資料洗掉。

### 計算方法（方法 C）

| KPI | 公式 |
|---|---|
| 製造人時/千瓶 | Σ(製造段 + 充填段 人·分) ÷ 60 ÷ Σ成品數(實際) × 1000 |
| 包裝人時/千瓶 | Σ(包裝工時 × 人數) ÷ Σ包裝瓶數 × 1000 |
| **全流程人時/千瓶** | 製造 + 包裝（**各自用自己的數量當分母，不交叉相除**） |
| 人力成本/瓶 | 全流程人時/瓶 × 工時費率 |
| 標準工時 | 近 12 個「資料齊全月份」的**中位數**，剔除離群值 |
| 效率異常 | 當月數值偏離標準工時 ±20%（初始門檻，存在 settings 可調整） |

離群值剔除沿用兩個系統現有的規則，不另外發明：

- 製造端：製成率系統的中位數＋MAD（`OUT_MIN_N=8`、`OUT_MZ=3.5`、`OUT_DEV=0.35`、`OUT_CAP=0.10`）
- 包裝端：包裝儀表板 v4 的比值門檻（0.5 ～ 2.5，工時 ≥ 1 小時）

少量品項某個月只有製造、沒有包裝時，改用**滾動 3 個月**計算。

### 資料齊全度檢核（統一檢核）

| # | 檢核 | 綠燈條件 |
|---|---|---|
| 1 | 製造資料已匯入 | `production.imports` 有該月份的記錄 |
| 2 | 包裝資料已月結 | 沿用 `packing.month_status`，漏登天數 = 0 |
| 3 | 物料平衡 | 近 3 個月包裝瓶數 ÷ 製造成品數落在 85%～115% |
| 4 | 人數填寫率 | 包裝批次有人數的比例 ≥ 95% |

**四項都綠燈的月份，才納入標準工時計算**，其他月份標示「暫定」。

## 五、風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 整合系統算出的製造工時，與製成率系統對不上 | 月會上出現兩個數字，失去信任 | 步驟 2 以「逐月數字一致」作為驗收門檻，規則直接沿用、不重寫邏輯 |
| 上傳錯檔（舊版或不完整的 Excel） | 資料被洗掉 | 匯入前預覽差異；筆數大減要二次確認；每次匯入都留記錄 |
| 長假期間沒人使用，Supabase 自動暫停 | 系統停擺 | 步驟 6 加每日自動連線 |
| 免費方案不能下載資料庫備份 | 誤刪無法還原 | 步驟 6 把 `production` 加進 Google Drive 每月備份 |
| repo 是公開的 | 資料外洩 | repo 只放程式，不放任何資料或 Excel；所有資料都要登入才讀得到 |
| 2026/2 以前的包裝沒有人數 | 那段期間算不出包裝人時 | 標示「無人數」、不納入標準工時；Jackie 哥取得資料後再補 |
