# 包裝產能與效率分析

資料來源：`包裝工時記錄表_2026.08.28.xlsx`（122 個工作表，109 個有資料）

- **儀表板**　`../index.html`　品項總覽、單一品項鑽取、排程試算、提醒、全廠趨勢
- **分析報告**　`plan.html`　分析前提、關鍵發現、方法論說明

## 給使用者：直接在網頁上傳自己的檔案

打開 `index.html`（或 GitHub Pages 網址）後，按 **「載入我的 Excel 檔」**，
選一份格式相同的 xlsx 即可，整頁會立刻用你的資料重算。

- **檔案只在你自己的瀏覽器裡計算，不會上傳、不會保存**，關掉分頁就沒了
- 需要 **Chrome / Edge 103 以上**（現場實測 Chrome 152 正常）
- 不依賴任何外部套件網站，內網擋外連也能用
- 若不上傳，看到的是頁面內建的那份資料

格式要求：每個工作表一個品項，第一列欄位固定為
`包裝日期`／`起始時間`／`結束時間`／`工時`／`瓶數`。
欄位不符或檔案不是 xlsx 時，畫面會明確告知哪裡不對，不會壞掉。

## 給維護者：更新內建資料（四步）

```bash
python3 analysis/scripts/extract.py <當月xlsx路徑>   # 解析 → analysis/rows.json
python3 analysis/scripts/audit.py                    # 檢核，有「必須修正」先回報
python3 analysis/scripts/payload.py                  # 報告用的彙總 → payload.json
python3 analysis/scripts/build.py                    # 把批次紀錄灌回 index.html
```

`build.py` 只替換 `index.html` 裡 `/*PAYLOAD:START*/ … /*PAYLOAD:END*/` 之間那段，
版面與程式碼不會被動到，可以重複執行。需要 `openpyxl`：`pip install openpyxl`

## 檔案

| 檔案 | 用途 |
|---|---|
| `scripts/rules.js` | **儀表板的計算引擎**：瀏覽器原生解 xlsx（zip + XML）＋ 全部指標與規則 |
| `scripts/extract.py` | 解析 xlsx，還原年份、處理混包寫法，逐列輸出 |
| `scripts/audit.py` | 資料檢核，分「必須修正」與「僅供判讀」兩級 |
| `scripts/payload.py` | 報告用的彙總（`plan.html` 使用） |
| `scripts/build.py` | 把批次紀錄灌回儀表板 |
| `rows.json` | 中間檔（1,571 筆逐批次紀錄） |
| `payload.json` | 報告用的彙總結果 |

**內建資料與上傳資料走同一條計算路徑**（`rules.js`），所以不會出現
「內建數字」跟「上傳後數字」對不起來的情況。

## 分析前提

這些前提決定了數字怎麼算，改了要重跑：

- **年份**　包裝日期欄沒有年份。資料以 10月→隔年9月 為一週期，10–12 月屬起始年、
  1–9 月屬次年。網頁上可用「起始年度」下拉調整。
- **工時**　＝（結束 − 起始）÷ 60，**掛鐘小時，不是人工時**。無作業人數欄位，
  因此所有「效率」數字代表線體速率，**不可用來評比人員**。
- **不新增欄位**　假設每次生產人數固定、不良率不納入，單純比較各品項包裝效率。
- **短批次**　全部納入計算，不排除；離群批次才在圖上特別標示。
- **混包**　瓶數欄如 `A200/B209` 代表同批混包兩種規格，加總處理（409 瓶）。
- **接單式生產**　批量與批次頻率由訂單與排程決定，**不是包裝單位可控**。
  因此「批次過碎」不列為異常，相關數據只提供給業務與生管參考。

## 主要指標

| 指標 | 定義 |
|---|---|
| 產能 | 瓶數 ÷ 工時 |
| 每千瓶工時 | 1000 ÷ 產能，可直接乘接單量 |
| 常態水準（P50） | 該品項各批次產能的中位數 —— 一半的批次做得到 |
| 合理目標（P75） | 第 75 百分位（線性內插）—— 每四批就有一批做得到 |
| 可省工時 | 目前工時 − 全數達合理目標所需工時。**理論上限，不是承諾** |
| 相對工時強度 | 全廠平均產能 ÷ 該品項產能。**須與工時佔比兩維度並用** |
| 每批相對表現 | 該批產能 ÷ 該品項中位數。1.0 ＝ 跟自己平常一樣 |
| 離群批次 | 該批產能 < 該品項**平均產能 × 0.7**，或 > 平均 × 2.5。<br>用平均而非中位數，是因為畫面上顯示、圖上畫線的就是平均產能，門檻可被使用者驗證。<br>係數定義在 `rules.js` 的 `OUT_LO` / `OUT_HI`，全廠約 213 批（16%） |

## 狀態燈號

| 燈號 | 判定 |
|---|---|
| 異常 | 連續 3 個生產月都比自己平常慢 10% 以上，或最近三個月出現離群批次 |
| 注意 | 批次落差偏大（CV > 40%） |
| 正常 | 其餘 |
| 批次太少 | 全年不到 10 批，樣本不足不做判定 |

門檻取自實際分布：47 支樣本足夠的品項中，CV 中位數為 35%，
若門檻設在 25% 會有 41 支被標黃，燈號就失去鑑別度。
